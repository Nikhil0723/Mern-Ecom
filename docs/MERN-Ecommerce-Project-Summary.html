MERN E-Commerce Project — Summary

Full-stack store: MongoDB, Express, React (Vite), Node.js

Current UI lives in client/ · API in backend/

Document date: 15 October 2026

1. What this project is

An online shop where customers browse products, search and filter, save a wishlist, use coupons, check out with shipping, and pay with Cash on Delivery or Razorpay. Admins run a panel for products, categories, orders, users, homepage offers, and coupons.

The React app uses Vite, Tailwind, shadcn/ui, Redux Toolkit, and React Router. The API uses Express, Mongoose, JWT, Cloudinary for images, and Razorpay for cards/UPI.

2. What people can do

Shoppers (guest)

  • Home: offer banners, categories, featured and latest products.
  • Shop: search, category filter, sort, pagination; product cards with wishlist and add-to-cart.
  • Product page: gallery, price, stock, quantity, reviews, add to cart / wishlist.
  • Cart: quantities, remove items, apply coupon, proceed to checkout (login required).

Logged-in customers

  • Register, login, forgot/reset password; edit profile (name, email, password).
  • Save a shipping address; wishlist; view order history and a single order.
  • Checkout: shipping → payment method (COD or Razorpay) → review/place order → pay if online.

Admins

  • Dashboard counts (products, orders, users).
  • CRUD products (image upload to Cloudinary), categories, offers/banners, coupons.
  • List users and delete them; list orders, open details, mark delivered.

4. Checkout flow

Cart → Login (if needed) → Shipping → Payment method → Place order → Razorpay (if online) or wait for COD → Order details. Cart is in Redux/localStorage; coupons are checked against the API.

7. How to run

  1. Backend .env: MONGO_URI, JWT_SECRET, PORT (optional, default 5000), FRONTEND_URL (e.g. http://localhost:5173), Cloudinary keys, Razorpay KEY_ID / KEY_SECRET.
  2. cd backend → npm install → npm run server.
  3. Client: VITE_API_URL pointing at the API (e.g. http://localhost:5000).
  4. cd client → npm install → npm run dev.
Admin screens are under /admin/* and need a user with isAdmin: true. Do not seed or wipe a production database.
